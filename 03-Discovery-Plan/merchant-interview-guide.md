# Merchant interview guide — Shopify Flow discovery

**Research objective:** Validate which merchants have a recurring automation job, how they currently handle it, where current tools create friction, and what evidence they need before activating automation.

## Participant profile

Recruit across three behavioural segments rather than using unsupported revenue thresholds:

- Early / low-complexity merchants.
- Growing operator-led merchants.
- Process-mature merchants with multiple systems or specialist support.

Aim for variation in industry, order complexity, app ecosystem, automation maturity and whether the participant personally configures workflows. Do not screen solely on GMV.

## 30–40 minute interview

### Intro and context (5 min)
1. Tell me about your role in running the store.
2. Which operational processes do you personally own?
3. What tools do you use day to day?

### Recent behaviour (10 min)
4. Tell me about the last time an order, inventory or customer-support exception needed attention.
5. Walk me through exactly what happened from the first signal to resolution.
6. How often does this type of issue happen?
7. What happens if it is missed or handled incorrectly?

### Current automation (10 min)
8. Which parts of that process are automated today?
9. Have you used Shopify Flow, templates, Sidekick or another automation tool? Please show me if possible.
10. What did you try to build? Where did you get stuck?
11. How do you test a workflow and know it is safe to activate?
12. What do you do when an app connection or an action fails?

### Trust and control (5–10 min)
13. Which actions would you allow to run automatically?
14. Which actions require approval?
15. What information would you want to see before turning a workflow on?
16. How do you detect and recover from a mistake?

### Prioritisation (5 min)
17. Which recurring operational problem would you most like to remove?
18. What have you already tried to solve it?
19. What would make a new solution meaningfully better than the current one?

## Observation tasks (optional)

Ask participants to think aloud while completing one or two tasks using their current tools:

- Create a workflow that tags high-value orders for review.
- Modify an existing workflow to apply only to a particular country.
- Test a workflow with one event that should pass and one that should fail.
- Configure an action that depends on a third-party app.

Do not use a real live store action. Use a test store or a sandbox and confirm that no customer-facing or financial action will execute.

## Note-taking template

| Field | Notes |
|---|---|
| Participant ID | Anonymous code |
| Segment behaviour | Early / growing operator-led / process-mature |
| Job | What they are trying to accomplish |
| Trigger | What event starts the work |
| Current workaround | Actual steps and tools |
| Frequency | Participant estimate; label as self-reported |
| Consequence | What happens when delayed or wrong |
| Friction | Observed, not inferred |
| Trust requirement | What evidence/control they need |
| Quote | Exact words, with permission |
| Opportunity | Researcher interpretation |
| Confidence | Low / medium / high |

## Research hygiene

- Do not lead participants with our proposed features.
- Ask about the last real occurrence, not what they think they might do.
- Separate observed behaviour, participant claims and researcher interpretation.
- Do not translate a single anecdote into a universal segment claim.
- Record counterexamples and disconfirming evidence.
